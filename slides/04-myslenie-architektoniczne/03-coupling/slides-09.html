Stamp coupling vs. data coupling

Stamp coupling
Cały obiekt „na zapas"
// dostaje cały obiekt User… function sendWelcomeEmail(user: User) { return mailer.send(user.email, …); } // User = { email: string, id: UUID, firstName: string, lastName: string, birthDate: Date, address: Address, paymentMethods: …, preferences: …, /* +20 pól */ }
  • Zależność od szerszej struktury niż faktyczna potrzeba
  • Zmiana w modelu rozlewa się tam, gdzie nie powinna
  • Pokusa cichego sięgania po inne pola w przyszłości
VS
Data coupling
Tylko to, co potrzebne
// dostaje wyłącznie to, czego używa function sendWelcomeEmail( to: Email, subject: string, body: string, ) { return mailer.send(to, subject, body); } // wywołanie: sendWelcomeEmail( user.email, "Witaj!", template.render(...), );
  • Moduł wprost deklaruje, czego potrzebuje
  • Mniejsza podatność na efekty uboczne i zmiany modelu
  • Oznaka dojrzałego projektowania interfejsu
